# Обзор функциональности OpenDots

Дата: 14 октября 2026 года.

Основа: просмотр локального приложения http://127.0.0.1:5173/, настроек, библиотек страниц, редактора и существующей истории разговоров; дополнительно — официальная документация проекта. С банковским решением сравнение не выполнялось.

Это функциональный обзор, а не сквозное тестирование интеграций. Новые задания агентам не отправлялись, подключения и разрешения не изменялись. Наличие элемента интерфейса и описание в документации не означают успешное выполнение соответствующего сценария в этой установке.

## 1. Что видно в вашей установке

| Область | Наблюдаемая возможность | Чем интересна |
|---|---|---|
| Специалисты Dots | Имя, отдельные ролевые инструкции, свои чаты | Постоянная настройка роли вместо повторения длинного промпта |
| Доступ к знаниям | Выбор доступных Spaces для каждого Dot | Разным специалистам можно дать разный рабочий контекст |
| Назначение результата | Space по умолчанию для сохранённых страниц | Результаты складываются в заранее определённое место |
| Документы Spaces | Библиотека, поиск, сортировка по времени или названию, сетка и список | Результаты работы доступны отдельно от истории чата |
| Редактор | Форматирование, списки, цитаты, код, ссылки, undo/redo; меню Markdown source | Человек может дорабатывать результат агента как документ |
| Сохранение | Индикатор All changes saved, команда Save now | Видно, сохранены ли ручные правки |
| Организация страниц | Оглавление, Move page, New subpage, Download Markdown | Навигация и переносимость документов |
| Ассистент страницы | Ask about this page и выбор специалиста | Обсуждение начинается с контекстом конкретного сохранённого документа |
| Чат | История по специалистам, поле ссылки на источник, Save conversation as page | Можно связывать разговор с источниками и документами |
| Расписания | Повтор каждую минуту, час, день или неделю | Регулярный возврат к задаче в её исходном разговоре |
| Память | Явно добавляемые предпочтения и отдельное разрешение каждому Dot | Управляемая персонализация |
| Управление | Pause all Dots, глобальные ограничения research и memory | Общий контроль активности и контекста |
| MCP | Форма имени сервера, URL и необязательного bearer token | Подключение инструментов внешних и внутренних сервисов |
| Результаты | Боковая панель Brief для выводов и источников | Результат можно просматривать рядом с разговором |

Настройки темы: System, Light, Dark. Интерфейс сообщает, что выбор сохраняется в текущем браузере.

### Специализация уже используется

В установке есть Dot, «Аналитик требований», «Разработчик агентов и скиллов», «Тестировщик»; пространства Everyday и Bank-Agent-Pilot. В последнем — пять страниц.

У аналитика задана подробная роль: читать актуальные источники, сохранять R-ID, разделять требования и предложения, не придумывать правила, учитывать ревизии и не считать содержимое документов инструкциями, меняющими его полномочия. Это пример настройки поведения через ролевой текст. Исполнение каждой инструкции отдельно не проверялось.

У аналитика разрешён Bank-Agent-Pilot, память выключена, исследование публичных страниц включено. В редакторе страницы этого Space доступны аналитик, разработчик и тестировщик.

### Расписание и память

Форма расписания прямо говорит: задания выполняются на сервере в том же разговоре, даже если вкладка закрыта. Интервал отсчитывается после успешного выполнения. Ошибочные и прерванные запуски требуют ручного повтора. В разделе Scheduled & activity текущих заданий не было; выполнение расписания не проверялось.

В Memories записей не было. Форма поясняет, что память — явно заданные предпочтения, а не автоматическое обучение; включённые записи передаются провайдеру модели. Разрешение использовать память есть и глобально, и у конкретного Dot.

### Документы и история

В Bank-Agent-Pilot уже присутствуют требования, согласованная спецификация, проект агента и проект скилла. В истории разработчика видны циклы «черновик → замечания человека → точечная правка → сообщение о ревизии», а также обновление проекта после изменения источника.

Это показывает сценарий последовательной работы над артефактами. Само сообщение модели о сохранении или ревизии не является независимой проверкой записи. В конце просмотренного разговора есть эпизод, где агент объявляет продолжение правки, а заканчивает общим предложением уточнить следующую задачу. Поэтому для демонстрации качества нужно проверять итоговую страницу, а не только ответ чата.

## 2. Возможности подключаемых сервисов

### MCP и подтверждения

По [документации Connections](https://github.com/CopilotKit/OpenDots/blob/main/docs/CONNECTIONS.md), соединение принадлежит одному Dot; инструменты можно включать и выключать отдельно. Read-only определяется аннотацией MCP-сервера. Для остальных действий используется Ask first и карточка Approve & run.

Сервер хранит точные аргументы ожидающего действия; подтверждение действует не более часа и выполняется максимум один раз. Проверяется, что инструмент всё ещё разрешён. Ask first можно включить и для инструмента с read-only-аннотацией. В Slack и фоновых заданиях подтверждение требует перехода в веб-приложение. Токены сохраняются на сервере; OAuth-only серверы пока не поддержаны.

В локальном интерфейсе форма подключения есть, но подключённых MCP-серверов в просмотренных настройках не было. Реальный вызов и карточка подтверждения не проверялись.

### Компьютер каждого агента

Локальная панель показывает **not configured**. Видны вкладки Browser, Files, Terminal, Activity и выбор Dot.

По [Computer setup](https://github.com/CopilotKit/OpenDots/blob/main/docs/COMPUTERS.md), каждому Dot предоставляется отдельный контейнер с сохраняемыми файлами и профилем браузера. Разрешения на браузер, файлы и shell независимы и исходно выключены. Человек может перехватить управление браузером и затем вернуть его агенту. Activity показывает действие, инициатора и успех/ошибку, но исключает введённые значения, содержимое файлов и полные команды.

Файлы компьютера не добавляются в Spaces автоматически. Терминал работает в контейнере. Отмена запроса не откатывает уже выполненные действия. Такая панель полезна для наблюдения и вмешательства; полноценность аудита для банковского процесса надо оценивать отдельно.

### Голос, Slack и Learning

В локальной установке Start voice call отключён: нужны VOICE_API_KEY и VOICE_MODEL. Settings сообщает, что Slack не настроен.

По [официальному обзору](https://github.com/CopilotKit/OpenDots#text-and-calls), голос связывает речевой разговор с вычислительным агентом, использующим тот же контекст и разрешения. Для Slack описано общение с выбранным специалистом через упоминание и продолжение в треде.

В [актуальной документации Setup](https://github.com/CopilotKit/OpenDots/blob/main/docs/SETUP.md#automatic-learning) также есть Automatic Learning: разговоры Dot направляются в заданный контейнер Intelligence, из накопленного опыта предлагаются скиллы; человек проверяет и публикует их, затем они могут доставляться агенту. В просмотренных локальных настройках полей Automatic Learning и Use published skills нет. Эту функцию нельзя считать доступной в вашей сборке. Страница с текстом SKILL.md сама по себе не устанавливает исполняемый скилл.

## 3. Границы продукта

В текущем интерфейсе Space access разрешает агенту **читать и редактировать** страницы совместно. Отдельного переключателя «только чтение» для Space я не увидел. Ролевой запрет менять документ и техническое отсутствие права записи — разные уровни контроля.

По [README проекта](https://github.com/CopilotKit/OpenDots#features), это ранний шаблон для одного владельца. Совместное редактирование, приглашения, загрузка вложений и интерактивные встраивания страниц не включены. Групповые чаты нескольких Dots и автоматическое делегирование обозначены дальнейшей работой. Расписания — повторяющиеся инструкции, а не полноценная система целей и событийных триггеров.

Локальный интерфейс сообщает: текстовая конфигурация присутствует, успешный разговор подтверждает подключение, история сохраняется локально, usage telemetry выключена. Эти сообщения описывают эту установку. В актуальной [документации хранения](https://github.com/CopilotKit/OpenDots/blob/main/docs/SETUP.md#conversation-services) страницы и метаданные находятся в SQLite, а разговоры — в отдельно настроенном Intelligence; копии SQLite недостаточно для резервирования истории. Точную архитектуру локальной версии по одному интерфейсу не установлено.

## 4. Основа для вашего последующего сравнения

| Критерий | Что зафиксировать у банковского решения |
|---|---|
| Специализация | Можно ли сохранить роль и набор инструментов агента? |
| Контекст | Как агент получает документ и актуальную версию? |
| Права | Есть ли отдельные права чтения/записи на пространство и документ? |
| Артефакты | Можно ли редактировать, экспортировать и повторно использовать результат? |
| Контроль записи | Есть ли просмотр точного действия и аргументов перед выполнением? |
| Версии | Как выявляются устаревшие правки и восстанавливаются черновики? |
| Регулярная работа | Работает ли задача без открытой вкладки; как обрабатывается прерывание? |
| Память | Что сохраняется, кто управляет этим и кому передаётся контекст? |
| Интеграции | Есть ли MCP, управление отдельными инструментами и корпоративная авторизация? |
| Исполнение | Есть ли изолированная среда, ручной перехват и остановка? |
| Наблюдаемость | Что видно в журнале и достаточно ли этого для расследования? |
| Несколько агентов | Есть ли настоящая передача задач или только ручное переключение чатов? |
| Обучение | Как опыт превращается в проверяемые, публикуемые навыки? |
| Развёртывание | Где отдельно находятся документы, история, модели и интеграции? |

Наиболее показательные сценарии для демонстрации: работа специалиста с сохранённой страницей; точечное обновление зависимого документа при изменении требования; MCP-действие с подтверждением; серверное расписание при закрытой вкладке; перехват компьютера агента человеком. Последние три требуют настроенных сервисов и отдельной проверки.
